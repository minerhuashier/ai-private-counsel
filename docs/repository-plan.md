# 公开仓库方案

状态：已确认  
确认日期：2026-11-18

## 定位

项目采用“协议优先、故事引子、工具逐步开源”的路线。传播主题可以是“AI 私人律师”，但产品能力和仓库名称必须明确为“AI 自诉助手”或“AI 诉讼辅助”。

核心差异点：

> 不只展示 AI 写了什么，而是展示如何证明 AI 写的内容可以被核验。

## 仓库隔离

### 公开仓库

- 只包含代码、协议、Schema、文档和虚构示例；
- 不包含真实姓名、案号、订单号、证据、录音、截图或法院文书；
- 默认使用本地数据和合成测试夹具；
- 任何真实材料都需要人工脱敏并重新制作公开副本。

### 私密工作区

- 保存原始证据和真实案件材料；
- 不设置公开远端；
- 不与公开仓库共用提交历史；
- 对外展示前单独生成脱敏版本。

## 许可证

- 代码：Apache-2.0；
- 文档与方法论：CC BY 4.0；
- 虚构示例数据：CC0 1.0；
- 项目名称、Logo 和品牌标识：保留权利。

## 初始版本范围

`v0.1.0` 只交付：

1. README 与项目边界；
2. AI 自诉工作协议；
3. 证据、事实、来源和批准 Schema；
4. 一个完全虚构的示例；
5. 公开仓库安全检查器；
6. 基础测试和贡献规范；
7. 协议总表、防止幻觉协议、“真实五问”提案、AEP 采用说明和项目初始化方法。

不在首版实现自动立案、自动提交、自动发送投诉、自动缴费或自动对外发布。

## 发布前安全检查

1. 确认没有真实案件文件和媒体；
2. 运行公开安全检查；
3. 运行测试；
4. 检查 Git 历史，而不只检查最新目录；
5. 启用 GitHub secret scanning、push protection 和依赖安全功能；
6. 经用户明确确认后才创建公开远端。
