# 工作流

## 目标

把一个混乱的纠纷材料集合，转化为可以逐项核验的事实、来源、问题与草稿。工作流不追求“一键生成”，而追求每次输出都能回答“依据在哪里”。

## 数据流

```text
原始材料
  -> 证据台账
  -> 时间线
  -> 事实矩阵
  -> 争议问题
  -> 官方来源
  -> 来源核验
  -> 证据-规则映射
  -> 文书草稿
  -> 本人复核
  -> 本人执行外部动作
```

## 步骤

### 1. 固定材料

对每份原始材料计算哈希，登记来源、取得时间和证明目的。原件只读，不因命名、裁剪或 OCR 而覆盖。

### 2. 建立时间线

时间线只记录可定位的事件。每个事件包含：

- 发生时间；
- 材料来源；
- 证据编号；
- 仍有争议或未知的部分。

### 3. 建立事实矩阵

事实矩阵至少区分：

- 客观事实；
- 本人感受；
- 法律主张或评价；
- 待核实信息。

### 4. 提炼争议问题

每个问题使用中性表述，例如“平台在何时知道何种信息”，而不是“平台故意包庇”。

### 5. 登记法律来源

只登记可追溯来源。记录标题、机关、文号、生效日期、官方 URL、抓取时间和哈希。

### 6. 建立映射

将“事实、争议问题、来源、诉讼请求或抗辩”连接起来。连接不成立时保留空白，不以推测补全。

### 7. 生成草稿

草稿保留来源编号和证据编号。无法核验的内容必须以占位符显示，不能被润色成确定事实。

### 8. 人工批准

用户确认事实、金额、日期、请求、版本和用途。批准只对特定版本和特定动作有效。

### 9. 审计

保存输入哈希、模型版本、输出哈希、人工修改和批准记录。外部动作由本人完成后单独登记。
